## 1. Назначение документа

Документ фиксирует **состав, назначение и границы элементов интерфейса** платформы ЯсноПро — категории «Элементы интерфейса» из [Архитектурной классификации](./YASNOPRO_ARCHITECTURE_CLASSIFICATION.md).

Документ нужен, чтобы:

- иметь единый источник истины для реестра «Элементы интерфейса» в DEV Studio;
- отделить **пользовательские зоны** от [ядра](./YASNOPRO_CORE_ARCHITECTURE.md), [служб](./YASNOPRO_PLATFORM_SERVICES.md), [модулей](./YASNOPRO_PLATFORM_MODULES.md), [данных](./YASNOPRO_PLATFORM_DATA.md) и **компонентов**;
- классифицировать новые UX-контуры по [Методике классификации](./YASNOPRO_ARCHITECTURE_CLASSIFICATION_METHODOLOGY.md);
- проектировать UX, компоненты, модули и публикации интерфейса.

## 2. Что такое элемент интерфейса

**Элемент интерфейса** — это **самостоятельная зона взаимодействия** пользователя с платформой, которую пользователь воспринимает как отдельную часть продукта.

### Принцип разделения

```text
Механизм ≠ Элемент интерфейса ≠ Компонент
```

| Уровень | Пример |
|---------|--------|
| **Ядро** (механизм) | Навигация, Отображения, Действия |
| **Служба** | Search Service |
| **Элемент интерфейса** | Боковое меню, Глобальный поиск, Карточка объекта |
| **Компонент** | PlatformMenu, SearchInput, PlatformCard |
| **Модуль** | Чат, Календарь, ЯСИИ |

### Элемент интерфейса не является

- **модулем** — целой продуктовой capability;
- **компонентом** — переиспользуемым строительным блоком UI;
- **данными** — хранимой информацией;
- **службой** — инфраструктурным сервисом;
- **механизмом ядра** — engine платформы.

### Отличие от других категорий

| Категория | Вопрос | Пример |
|-----------|--------|--------|
| **Ядро** | *Как устроено?* | View Engine, Navigation Engine |
| **Служба** | *Кто обслуживает?* | Search Service |
| **Модуль** | *Какую функцию даёт компания?* | Документы, Чат |
| **Данные** | *Что хранится?* | Настройки пользователя |
| **Компонент** | *Из чего собран UI?* | PlatformModal |
| **Элемент интерфейса** | *Что видит и нажимает пользователь?* | Боковое меню |

## 4. Состав элементов интерфейса v1.0

Ниже — **20 элементов** реестра с карточками.

---

### Группа 1. Глобальная оболочка

---

#### Боковое меню

`component_key`: **`side-navigation`**

**Назначение**  
Основная навигация по разделам tenant в Office и Studio.

**Что делает**  
Показывает дерево разделов; позволяет перейти к страницам, модулям и объектам.

**Кто использует**  
Все пользователи tenant.

**Почему элемент интерфейса**  
Пользователь называет «левое меню»; самостоятельная зона с навигационной ролью. Механизм **Навигация** — ядро.

**Что произойдёт при отсутствии**  
Нет структурированных переходов по порталу.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Ядро (Навигация), Компоненты  
**Статус:** Draft  
**Уверенность:** Высокая

---

#### Верхняя панель

`component_key`: **`top-navigation`**

**Назначение**  
Глобальная «шапка» приложения на всех основных экранах.

**Что делает**  
Объединяет бренд, поиск, уведомления, профиль; задаёт горизонтальную оболочку.

**Кто использует**  
Все пользователи.

**Почему элемент интерфейса**  
Узнаваемая зона; не отдельный виджет и не модуль.

**Что произойдёт при отсутствии**  
Нет единой точки доступа к глобальным действиям.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Компоненты, Пользовательский блок (дочерние зоны)  
**Статус:** Draft  
**Уверенность:** Высокая

---

#### Хлебные крошки

`component_key`: **`breadcrumbs`**

**Назначение**  
Ориентация пользователя «где я» в иерархии разделов.

**Что делает**  
Показывает цепочку от корня до текущей страницы; позволяет вернуться на уровень выше.

**Кто использует**  
Все пользователи при глубокой навигации.

**Почему элемент интерфейса**  
Отдельный UX-контур ориентации, не кнопка и не данные.

**Что произойдёт при отсутствии**  
Пользователь теряется в глубоких разделах.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Ядро (Навигация)  
**Статус:** Draft  
**Уверенность:** Высокая

---

#### Вкладки рабочей области

`component_key`: **`workspace-tabs`**

**Назначение**  
Переключение между открытыми разделами и страницами внутри workspace.

**Что делает**  
Держит несколько «открытых мест» работы; закрытие и переключение вкладок.

**Кто использует**  
Пользователи Office и Studio.

**Почему элемент интерфейса**  
Самостоятельный паттерн multi-tab; механизм workspace — ядро.

**Что произойдёт при отсутствии**  
Только один экран за раз; хуже многозадачность.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Ядро (Навигация, Композиция портала), Данные (User Settings)  
**Статус:** Draft  
**Уверенность:** Высокая

### Группа 2. Пользовательский блок

#### Аватар пользователя

**Назначение**

#### Глобальный поиск

`component_key`: **`global-search`**

**Назначение**  
Единая точка поиска по платформе: объекты, страницы, разделы.

**Что делает**  
Принимает запрос; показывает результаты discovery; переход к найденному.

**Кто использует**  
Все пользователи; аналитики, администраторы.

**Почему элемент интерфейса**  
Пользователь видит «строку поиска»; **Search Service** — служба.

**Что произойдёт при отсутствии**  
Поиск только внутри отдельных модулей; хуже orientation.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Службы (Search Service), Данные  
**Статус:** Draft  
**Уверенность:** Высокая

#### Центр уведомлений

`component_key`: **`notification-center`** (legacy: `notification-bell`)

**Назначение**  
Агрегированный просмотр уведомлений пользователя (список, overlay, история).

**Что делает**  
Открывается из колокола в header; показывает что требует внимания; переход к контексту.

**Кто использует**  
Все пользователи tenant.

**Почему элемент интерфейса**  
UI-контур потребления уведомлений; **модуль «Уведомления»** — продукт; **Notification Dispatch** — служба.

**Что произойдёт при отсутствии**  
События не видны в агрегированном виде.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Модули (Уведомления), Службы, Данные  
**Статус:** Draft  
**Уверенность:** Высокая

---

#### Точка входа в настройки

`component_key`: **`settings-entry`** (legacy: `settings-button`)

**Назначение**  
Быстрый доступ к настройкам текущего контекста: страница, вид, workspace, пользователь.

**Что делает**  
Иконка или пункт «Настройки»; открывает панель или страницу настроек.

**Кто использует**  
Пользователи в режиме редактирования; администраторы.

**Почему элемент интерфейса**  
Отдельная точка входа в UX; сами настройки — **данные**.

**Что произойдёт при отсутствии**  
Настройки спрятаны; сложнее персонализация.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Данные (User Settings, Tenant Configuration), Компоненты  
**Статус:** Draft  
**Уверенность:** Высокая

#### Поверхность представления

`component_key`: **`view-surface`**

**Назначение**  
Зона, где пользователь **видит набор записей** объекта в выбранном виде.

**Что делает**  
Host для таблицы, дерева, доски, календаря и других view types.

**Кто использует**  
Все пользователи Office.

**Почему элемент интерфейса**  
«Таблица проектов» — рабочая область; **View Engine** — ядро.

**Что произойдёт при отсутствии**  
Нет стандартного места для списков и регistries объектов.

> **Таблица, Дерево, Доска, Календарь** — **не отдельные элементы реестра v1.0**.  
> Это **разновидности поверхности представления**, определяемые ядром (типы отображений).

**Основная категория:** Элементы интерфейса

**Статус:** Draft  
**Уверенность:** Средняя

Нет стандартного паттерна вторичных задач на месте.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Компоненты, Стандарты (Platform Modal Standard)  
**Статус:** Draft  
**Уверенность:** Высокая

#### Боковая панель

`component_key`: **`side-panel`**

**Назначение**  
Выезжающая или закреплённая панель сбоку экрана.

**Что делает**  
Фильтры, детали, помощь, вторичные формы без полного modal.

**Кто использует**  
Пользователи списков, досок, карточек.

**Почему элемент интерфейса**  
Отдельный паттерн drawer/side panel.

**Что произойдёт при отсутствии**  
Всё через modal или отдельные страницы.

**Основная категория:** Элементы интерфейса  
**Связанные категории:** Компоненты  
**Статус:** Draft  
**Уверенность:** Высокая

## 5. Спорные элементы

Следующие элементы **не включены** в состав v1.0; требуют решения перед расширением реестра.

---

### Рабочий стол (Home Workspace)

**За включение:** домашняя точка после входа; пользователь называет «рабочий стол».  
**Против:** **Workspace и композиция портала — ядро**; home — конфигурация страницы, не отдельный UX-примитив.  
**Предварительное решение:** **не включать в v1.0**; описать как композицию **Вкладок + Поверхностей** на home page.  
**Следующее действие:** уточнить в документе «Композиция портала» (ядро) vs product naming «Desktop».

---

### Панель администратора компании

**За включение:** отдельный admin UX для tenant.  
**Против:** **целый продуктовый контур** (много страниц); ближе к **подсистеме Tenant Administration**, не atomic UI element.  
**Предварительное решение:** **не включать в v1.0** как один элемент; admin screens — набор страниц в **боковом меню**.  
**Следующее действие:** при необходимости — категория «Платформенные экраны» в v1.1.

---

### Control Plane

**За включение:** отдельный UI владельца платформы.  
**Против:** **Control Plane — архитектурный контур** (UI + registry + orchestrator), не один элемент интерфейса.  
**Предварительное решение:** **не включать**; CP UI декомпозируется на те же элементы (меню, таблицы, панели).  
**Следующее действие:** отдельный architecture map Control Plane UI (вне реестра «Элементы»).

---

## 6. Границы категории

### Что не относится к элементам интерфейса

Исключение из реестра не означает отсутствие в продукте.

#### Ядро (механизмы)

- Объекты, Поля, Связи, Действия, Процессы, События, **Навигация** — engines
- На экране проявляются через **элементы интерфейса** и **компоненты**

#### Службы

- Session Bridge, Provisioning, Publication Service, Search Service, AI Context Service

#### Модули

- Чат, Календарь, Документы, Уведомления, BPMN, ЯСИИ — **целые продукты**; entry points могут совпадать с элементами (колокол, пункт меню)

#### Данные

- Метаданные, Записи, Настройки, Журналы, Каталоги

#### Компоненты

- PlatformModal, PlatformButton, PlatformTable, PlatformTabs, PlatformCard, PlatformInput

## 7. Карта взаимодействия

```text
Переключатель контекста
  → Боковое меню / Верхняя панель
    → Вкладки рабочей области
      → Поверхность представления
        → Карточка объекта
          → Панель свойств
          → Панель действий
          → Контекстное меню

Боковое меню
  → Избранное и недавние
  → Раздел модуля (Модуль — отдельная категория)

Глобальный поиск
  → Карточка объекта / Поверхность представления

Центр уведомлений
  → Модуль «Уведомления» (переход по контексту)
  → Карточка объекта / Процесс

Меню пользователя
  → Точка входа в настройки
  → Данные (User Settings)

Быстрое создание / Панель выбора
  → Модальная зона / Боковая панель
    → Бизнес-запись (Данные)

Хлебные крошки
  → Навигация вверх по иерархии (Ядро)
```

## 8. Использование документа

Документ используется для:

- **наполнения реестра «Элементы интерфейса»** в DEV Studio (после утверждения Draft);
- **классификации новых UX-контуров** — элемент vs компонент vs модуль;
- **проектирования UX** — стандартные зоны Office/Studio/CP;
- **проектирования компонентов** — какие platform components обслуживают какие элементы;
- **проектирования модулей** — граница module screen vs platform chrome;
- **проектирования публикаций интерфейса** — какие UI-контуры входят в release scope.
