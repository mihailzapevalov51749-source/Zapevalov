## 1. Назначение документа

Документ фиксирует **состав, границы и потоки данных** платформы ЯсноПро — категории «Данные» из [Архитектурной классификации](./YASNOPRO_ARCHITECTURE_CLASSIFICATION.md).

Документ нужен, чтобы:

- иметь единый источник истины для реестра «Данные платформы» в DEV Studio;
- отделить **контуры данных** от [ядра](./YASNOPRO_CORE_ARCHITECTURE.md), [служб](./YASNOPRO_PLATFORM_SERVICES.md), [модулей](./YASNOPRO_PLATFORM_MODULES.md), runtime и UI-компонентов;
- классифицировать новые сущности по [Методике классификации](./YASNOPRO_ARCHITECTURE_CLASSIFICATION_METHODOLOGY.md);
- проектировать публикации, релизы, миграции и каталог решений.

Документ основан на аудитах **WI-ARCH-DATA-001**, нормализации **WI-ARCH-DATA-001A** (14 контуров → **11 элементов реестра**) и синхронизации реестра **WI-ARCH-REG-DATA-002**.  
Техническая реализация, API, код и таблицы БД **не входят** в scope документа.

## 2. Что такое данные платформы

**Данные платформы** — это информация, которая **хранится**, **изменяется**, **используется** платформой или **передаётся** между контурами DEV, TEMPLATE и CLIENT.

### Принцип разделения

```text
Механизм ≠ Данные механизма
```

| Механизм (не данные) | Данные механизма |
|----------------------|------------------|
| Process Engine | Process Definitions, состояния экземпляров |
| Session Bridge | Данные сессии и маршрутизации *(операционные)* |
| Publication Service | Release & Deployment Artifacts, Published Metadata |
| File Service | File Metadata |
| Event Engine (ядро) | Journal Data |

### Что считается данными

- **Контур или класс** хранимой информации (метаданные структуры, бизнес-записи, журналы).
- **Артефакты** lifecycle (release package, provenance).
- **Настройки** компании и пользователя.
- **Доменные данные** модулей (сообщения чата, события календаря).

### Что не считается данными (в реестре)

- **Конкретная запись** «Проект №47» — экземпляр tenant, не архитектурная сущность реестра.
- **Исполняемый код** служб и ядра.
- **UI-компоненты** и **runtime-среды**.

### Отличие от других категорий

| Категория | Вопрос | Пример |
|-----------|--------|--------|
| **Ядро** | *Как работает механизм?* | Entity Layer, Process Engine |
| **Данные** | *Что хранится?* | Бизнес-записи, метаданные структуры |
| **Службы** | *Кто обслуживает?* | Publication Service, File Service |
| **Модули** | *Что видит пользователь?* | Чат, Календарь |
| **Runtime** | *Где исполняется?* | DEV, TEMPLATE, CLIENT |
| **Компоненты** | *Как выглядит UI?* | PlatformModal |

### Метаданные структуры

**Назначение**  
Описание **структуры компании как системы**: объекты (Клиенты, Проекты, Задачи), поля, связи, представления, действия, навигация — в design-time и runtime-canonical виде.

**Что входит**

- **Метаданные конструктора** — черновики структуры в DEV (authoring).
- **Опубликованные метаданные** — каноническая структура для TEMPLATE и CLIENT после публикации.

**Что не входит**

- Object Schema как отдельный контур — это **логический вид** той же информации.
- Конкретные бизнес-записи tenant.
- Publication Service — **служба** доставки.

**Источник истины**

- В DEV: **метаданные конструктора**.
- В CLIENT runtime: **опубликованные метаданные** (производные от конструктора через публикацию).

**Кто использует**  
Studio, Publication Service, Office, модули, ядро (runtime), ЯСИИ.

**Что произойдёт при отсутствии**  
Runtime не знает, какие объекты и экраны существуют в компании.

**Основная категория:** Данные  
**Связанные категории:** Ядро, Публикация, Runtime  
**Статус:** Draft  
**Уверенность:** Высокая

> **Object Schema не является отдельным контуром данных.**  
> Схема типов, полей и связей — абстракция, общая для метаданных конструктора и опубликованных метаданных.

---

### Бизнес-записи

**Назначение**  
**Основные записи (экземпляры объектов)** компании: проекты, задачи, клиенты, карточки.

**Что входит**  
Значения полей, статусы, версии записей tenant (object-centric business data).

**Что не входит**

- Entity Engine — **ядро** (механизм).
- Метаданные объектов (виды «Клиенты», «Задачи») — **метаданные структуры**.
- Связи между записями — **экземпляры связей**.

**Sub-контур (не отдельная запись реестра):** **Коммуникации на объектах** — комментарии, заметки; вложения **ссылаются** на метаданные файлов.

**Источник истины**  
Tenant runtime — записи создаются и изменяются пользователями и процессами.

**Кто использует**  
Office, модули, отображения, процессы, ЯСИИ.

**Что произойдёт при отсутствии**  
Портал без содержимого — только пустая оболочка конструктора.

**Основная категория:** Данные  
**Связанные категории:** Ядро (Объекты)  
**Статус:** Draft  
**Уверенность:** Высокая

---

### Экземпляры связей

**Назначение**  
**Связи между записями**: «задача → проект», иерархии, графы отношений.

**Что входит**  
Экземпляры relation definitions между business records.

**Что не входит**

- Relation Engine — **ядро**.
- Определения связей в метаданных — **метаданные структуры**.

**Источник истины**  
Tenant runtime; создаются пользователями, импортом, процессами.

**Кто использует**  
Ядро, отображения, процессы, модули, ЯСИИ.

**Что произойдёт при отсутствии**  
Данные изолированы; нет модели компании как системы связей.

> **Связи являются самостоятельным контуром данных** — не «полями» записи и не дублем бизнес-записей.

**Основная категория:** Данные  
**Связанные категории:** Ядро (Связи)  
**Статус:** Draft  
**Уверенность:** Высокая

---

### Пользователи и права доступа

**Назначение**  
**Идентификационная и авторизационная информация**: пользователи, членства в компании, роли, права.

**Что входит**

- Глобальные и platform-level пользователи.
- Membership tenant.
- Роли и effective permissions *(как хранимая модель)*.

**Что не входит**

- Session Bridge, Platform Identity Service — **службы**.
- Модель доступа как механизм — **ядро (Доступ)**.

**Источник истины**  
Control Plane (platform users) + tenant admin (membership, roles).

**Кто использует**  
Все подсистемы, Session Bridge, модули, ЯСИИ.

**Что произойдёт при отсутствии**  
Никто не привязан к компании; нет авторизации.

**Основная категория:** Данные  
**Связанные категории:** Ядро (Доступ), Службы  
**Статус:** Draft  
**Уверенность:** Высокая

### Настройки компании

**Назначение**  
**Параметры tenant**: брендинг, доменные настройки, безопасность, настройки портала, включённые модули.

**Что входит**  
Configuration scope компании — не бизнес-записи и не user preferences.

**Что не входит**

- Provisioning — **служба** создания компании.
- Метаданные структуры объектов.

**Источник истины**  
Tenant administration; baseline из TEMPLATE при provisioning.

**Кто использует**  
Администраторы, модули, runtime, Publication.

**Что произойдёт при отсутствии**  
Компания не персонализирована; модули не знают конфигурацию tenant.

**Основная категория:** Данные  
**Связанные категории:** Модули, Runtime  
**Статус:** Draft  
**Уверенность:** Высокая

---

### Пользовательские настройки

**Назначение**  
**Персональные параметры** пользователя: профиль, предпочтения, избранное, последние действия, персонализация workspace.

**Что входит**  
User-scoped settings и preferences.

**Что не входит**

- Tenant configuration — **настройки компании**.
- Роли и права — **пользователи и права доступа**.

**Источник истины**  
Пользователь и Office runtime.

**Кто использует**  
Office, элементы интерфейса, модули.

**Что произойдёт при отсутствии**  
Каждый вход «с нуля»; нет персональной рабочей среды.

**Основная категория:** Данные  
**Связанные категории:** Элементы интерфейса  
**Статус:** Draft  
**Уверенность:** Высокая

### Данные модулей

**Назначение**  
**Доменные данные** платформенных модулей — содержимое, которое создают модули, а не конструктор объектов.

**Что входит (поддомены)**

| Поддомен | Содержание |
|----------|------------|
| Данные чата | Сообщения, каналы, участники |
| Данные календаря | События, приглашения |
| Данные документов | Записи библиотек, версии |
| Данные уведомлений | Записи уведомлений *(не dispatch)* |
| Данные BPMN | Определения диаграмм процессов |
| Данные ЯСИИ | Memory, corpus, knowledge *(спорная граница со службой)* |

**Что не входит**

- Сами модули (Чат, Календарь…) — **модули** как capability.
- File Service — **служба**; бинарники — через **метаданные файлов**.

> **Один элемент реестра, несколько доменов данных.**

**Источник истины**  
Соответствующий модуль + tenant scope.

**Кто использует**  
Модули, Office, ЯСИИ, процессы.

**Что произойдёт при отсутствии**  
Модули без памяти — только UI-оболочки.

**Основная категория:** Данные  
**Связанные категории:** Модули, Службы  
**Статус:** Draft  
**Уверенность:** Высокая

### Платформенный каталог

**Назначение**  
**Master data платформы**: реестр компаний, каталоги модулей и решений, платформенные справочники Control Plane.

**Что входит**

- Компании (customer companies registry).
- Каталог модулей платформы.
- Каталог решений *(product contour)*.
- Platform roles и registry rows CP.

**Что не входит**

- Release artifacts — **данные публикации**.
- Бизнес-данные tenant.

**Источник истины**  
Control Plane.

**Кто использует**  
Control Plane, Provisioning, Publication, владелец платформы.

**Что произойдёт при отсутствии**  
Нет учёта компаний и платформенных артефактов на уровне CP.

**Основная категория:** Данные  
**Связанные категории:** Службы, Runtime  
**Статус:** Draft  
**Уверенность:** Высокая

### Данные публикации и эксплуатации

**Назначение**  
**Lifecycle платформы**: релизы, деплойменты, provenance, операционное состояние сред.

**Что входит**

- **Пакеты релизов** — Release Package, manifest, BOM.
- **Состав релизов** — Release Scope, Release Candidate.
- **Подтверждение происхождения** — Provenance *(производное от release + journals)*.
- **Состояние среды** — version pin, deployment state *(операционное зеркало)*.

**Что не входит**

- Publication Service, Deployment Execution — **службы**.
- Published Metadata — **метаданные структуры** *(результат публикации, отдельный контур)*.

> **Часть данных производна от публикации** — Provenance и Runtime State не authoring SoT.

**Источник истины**  
Control Plane + release pipeline; authoritative version — release artifact.

**Кто использует**  
Control Plane, Publication Service, Provisioning, Deployment Execution.

**Что произойдёт при отсутствии**  
Нет трассируемости «что доставлено куда»; риск рассинхрона сред.

**Основная категория:** Данные  
**Связанные категории:** Публикация, Службы, Runtime  
**Статус:** Draft  
**Уверенность:** Высокая

### Журналы

**Назначение**  
**Append-only записи** аудита, событий и dev-разработки.

**Что входит**

- **Platform Event Journal** — platform-scope audit.
- **Tenant Event Journal** — события компании.
- **DEV Journal** — записи разработки в DEV tenant.

**Что не входит**

- Event Engine — **ядро (События)** — механизм фиксации.
- Конкретное «событие» как абстракция — **ядро**; **журнал** — **хранилище записей**.

> **Журнал ≠ Событие.**  
> Событие относится к **ядру**. Журнал относится к **данным**.

**Источник истины**  
Platform и tenant event pipelines; DEV journal — dev_development scope.

**Кто использует**  
Control Plane, аудит, DEV Studio, ЯСИИ (evidence), владелец платформы.

**Что произойдёт при отсутствии**  
Нет истории изменений; нарушается ADR-AUD-001.

**Основная категория:** Данные  
**Связанные категории:** Ядро (События), Стандарты  
**Статус:** Draft  
**Уверенность:** Высокая

---

### Метаданные файлов

**Назначение**  
**Структурированная информация о файлах**: ссылки, версии, права, привязка к объектам и модулям.

**Что входит**  
File metadata records; не бинарное содержимое.

**Что не входит**

- File Service — **служба** хранения и выдачи.
- Сами файлы как bytes — инфраструктура службы.

> **Файл ≠ Метаданные файла.**

**Источник истины**  
File Service + owning domain (объект, чат, документ).

**Кто использует**  
Документы, чат, объекты, модули, коммуникации на объектах.

**Что произойдёт при отсутствии**  
Файлы есть, но система не знает, к чему они относятся и кому доступны.

**Основная категория:** Данные  
**Связанные категории:** Службы (File Service), Модули  
**Статус:** Draft  
**Уверенность:** Высокая

## 6. Границы данных

### Что не является данными (в смысле реестра)

Механизмы и capability — другие категории; *их stores* — **данные** выше.

#### Ядро (механизмы, не контуры реестра «Данные»)

- Объекты, Поля, Связи, Действия, Процессы, События — **как engines**
- *Записи и definitions* — **данные** (бизнес-записи, метаданные, journal)

#### Службы

- Session Bridge, Provisioning, Publication Service, Search Service, AI Context Service

#### Модули (функциональность)

- Чат, Календарь, Документы, Уведомления, BPMN, ЯСИИ

#### Runtime (среды)

- DEV, TEMPLATE, CLIENT

#### Компоненты

- PlatformModal, PlatformTabs, PlatformButton

  → Коммуникации на объектах
    → (вложения → Метаданные файлов)

## 8. Использование документа

Документ используется для:

- **наполнения реестра «Данные»** в DEV Studio (после утверждения Draft);
- **архитектурного аудита** — «это данные или механизм?»;
- **классификации новых сущностей**;
- **проектирования публикаций** — Designer → Published Metadata;
- **проектирования релизов** — Release & Operations Data;
- **проектирования миграций** — контур и ownership данных;
- **проектирования каталога решений** — отделение solution data от platform data.
