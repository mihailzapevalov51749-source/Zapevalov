## 1. Назначение

Документ является **единым источником описания публикуемой конфигурации** платформы ЯсноПро — категории «Конфигурация», дополняющей [Архитектурную классификацию](./YASNOPRO_ARCHITECTURE_CLASSIFICATION.md).

Документ нужен, чтобы:

- зафиксировать **как архитектурные элементы собраны и опубликованы** для пользователя tenant;
- отделить конфигурацию от [ядра](./YASNOPRO_CORE_ARCHITECTURE.md), [модулей](./YASNOPRO_PLATFORM_MODULES.md), [данных](./YASNOPRO_PLATFORM_DATA.md), [элементов интерфейса](./YASNOPRO_INTERFACE_ELEMENTS.md), **Runtime** и **Публикации**;
- использовать при формировании релизов, публикации изменений, создании компаний, аудитах и онбординге.

Документ основан на аудитах **WI-ARCH-CONFIG-001** и нормализации **WI-ARCH-CONFIG-001A** (**28 элементов** реестра v1.0 в **10 группах**).  
Реестр Architecture Navigator v1.1: **36 строк** (10 групп + 26 дочерних), см. §4.1.  
Код, API, таблицы БД и реализация **не входят** в scope документа.

**Где применяется:** архитектура платформы, Designer publish, Control Plane, provisioning, Release Scope, Office runtime, аудиты конфигурации.

## 2. Что такое конфигурация

**Конфигурация** — это **опубликованная сборка** того, как пользователь видит и использует платформу в runtime Office: навигация, страницы, рабочие пространства, размещение объектов и модулей, оболочка интерфейса, действия и стартовые параметры компании.

### Главный вопрос категории

| Категория | Вопрос |
|-----------|--------|
| **Архитектура (ядро, модули, данные…)** | *Что существует в платформе?* |
| **Конфигурация** | *Как это собрано, настроено и опубликовано для пользователя?* |

### Конфигурация не является

- **механизмом ядра** (навигация, действия, view engine — engines);
- **модулем** (capability «Чат», «Календарь»);
- **метаданными** object type / field (Structure Metadata);
- **бизнес-записью** tenant;
- **элементом интерфейса** (taxonomy UX-зон);
- **компонентом** (PlatformSidebar, PlatformModal);
- **Runtime** (среда DEV / Эталон / Компания);
- **Публикацией** (конвейер доставки изменений).

### Конфигурация — самостоятельная категория

**Конфигурация не входит в Runtime.** Runtime отвечает *где исполняется*; конфигурация — *что materialized для UX* внутри runtime компании.

## 3. Роль конфигурации в архитектуре ЯсноПро

```text
Архитектура (ядро, модули, метаданные, UI taxonomy)
        ↓ проектирование в Designer / DEV
Конфигурация (publish snapshot — «что увидит пользователь»)
        ↓ доставка
Публикация (Release Package, apply, verify)
        ↓ materialization
Компания (изолированная среда, Office runtime)
        ↓ потребление
Пользователь
```

**Источник конфигурации:** publish каталога tenant (Designer → Эталон → компания).  
**Хранение:** контур [Данных](./YASNOPRO_PLATFORM_DATA.md) «Настройки компании» и materialized catalog; **архитектурная роль** — категория «Конфигурация».

## 5. Навигация

Содержимое **бокового меню** и дерева разделов — конфигурация; **механизм навигации** — [ядро](./YASNOPRO_CORE_ARCHITECTURE.md).

---

#### Структура навигации

**Назначение**  
Опубликованное дерево разделов tenant.

**Что увидит пользователь**  
Боковое меню целиком: разделы верхнего уровня и вложенность.

**При изменении**  
Изменится состав и форма левого меню.

**Связанные категории:** Ядро (Навигация), Элементы интерфейса (боковое меню), Данные (navigation items)

---

#### Пункты меню

**Назначение**  
Конкретные entries навигации: страница, объект, модуль, системный раздел.

**Что увидит пользователь**  
Пункты «Проекты», «Документы», «Настройки».

**При изменении**  
Появится или исчезнет пункт; изменится переход.

**Связанные категории:** Страницы, Размещение объектов, Размещение модулей

---

#### Порядок и иерархия

**Назначение**  
Sort order, parent/child, группы в меню.

**Что увидит пользователь**  
Порядок пунктов и вложенные папки.

**При изменении**  
Разделы переедут выше/ниже; изменится группировка.

**Связанные категории:** Ядро (Навигация)

---

#### Иконки и подписи

**Назначение**  
Display-атрибуты пункта меню (не id).

**Что увидит пользователь**  
Иконка и название в меню.

**При изменении**  
Другой вид пункта без смены target.

**Связанные категории:** Стандарты UI, Данные (display fields)

---

#### Точки входа модулей в меню

**Назначение**  
Привязка [модуля](./YASNOPRO_PLATFORM_MODULES.md) к пункту навигации.

**Что увидит пользователь**  
«Календарь», «Чат» в боковом меню.

**При изменении**  
Модуль появится или исчезнет из меню.

**Связанные категории:** Модули, Размещение модулей

---

## 6. Страницы

Композиция Portal → Page → Section → Block ([Portal Composition Model](./YASNOPRO%20Portal%20Composition%20Model.md)); **published pages** — конфигурация.

---

#### Каталог страниц

**Назначение**  
Реестр страниц, доступных в runtime tenant.

**Что увидит пользователь**  
Набор экранов, на которые можно перейти из меню и workspace.

**При изменении**  
Новая или удалённая страница в портале.

**Связанные категории:** Ядро (Композиция портала), Публикация

---

#### Композиция страницы

**Назначение**  
Sections и blocks на странице после publish.

**Что увидит пользователь**  
Расположение блоков: таблица, текст, виджет.

**При изменении**  
Другой layout экрана; другие блоки на той же странице.

**Связанные категории:** Компоненты, Ядро (Отображения)

---

#### Домашняя страница

**Назначение**  
Стартовый экран после входа (workspace home, system home).

**Что увидит пользователь**  
«Рабочий стол» / главная tenant.

**При изменении**  
Другой стартовый экран; иной первый контекст работы.

**Связанные категории:** Рабочие пространства, Стандарт системных сущностей (ADR-007)

---

#### Шаблоны компоновки

**Назначение**  
Опубликованные layout templates для типов страниц.

**Что увидит пользователь**  
Единообразие экранов Studio/Office одного класса.

**При изменении**  
Новые страницы наследуют другой шаблон.

**Связанные категории:** Стандарты интерфейса, Компоненты (PlatformPage)

## 7. Рабочие пространства

---

#### Рабочие пространства

**Назначение**  
Определения workspace tenant (platform-level, не personal).

**Что увидит пользователь**  
Контекст «где я работаю» в Office.

**При изменении**  
Новое или изменённое рабочее пространство.

**Связанные категории:** Ядро (Композиция портала), Элементы интерфейса (вкладки)

---

#### Вкладки рабочих пространств

**Назначение**  
Platform-defined вкладки в полосе workspace (не user tabs).

**Что увидит пользователь**  
Открытые по умолчанию вкладки сверху.

**При изменении**  
Новая системная вкладка; другой набор при старте.

**Связанные категории:** Элементы интерфейса (вкладки рабочей области)

---

#### Системные вкладки

**Назначение**  
Home tab, system pages (System Entity + publish).

**Что увидит пользователь**  
«Главная», служебные вкладки shell.

**При изменении**  
Изменится home entry point.

**Связанные категории:** ADR-007, Навигация

---

### Почему персональные вкладки не конфигурация

**Персональные вкладки** создаёт пользователь при работе (открыл раздел, закрыл, порядок) — это **пользовательские настройки** ([Данные](./YASNOPRO_PLATFORM_DATA.md) «Пользовательские настройки»), не publish tenant.

| | Platform workspace tabs | Personal tabs |
|---|-------------------------|---------------|
| Кто задаёт | Analyst / publish | Пользователь |
| Scope | Tenant | User |
| Категория | **Конфигурация** | **Данные** |

## 8. Размещение объектов

---

#### Публикация объектов

**Назначение**  
Какие **объекты** (виды сущностей) **доступны** в runtime компании после publish.

**Что увидит пользователь**  
Экземпляры объектов в меню, списках, карточках.

**При изменении**  
Новый объект в Office; объект скрыт из runtime.

**Связанные категории:** Ядро (Объект, Экземпляры объектов), Данные (Structure Metadata)

---

#### Публикация представлений

**Назначение**  
Опубликованные views / representations для объектов.

**Что увидит пользователь**  
Таблица, план, карточка — как настроено для tenant.

**При изменении**  
Другой default view; новое представление в списке.

**Связанные категории:** Ядро (Отображения), Компоненты (View Type Renderer)

---

#### Привязка объектов к навигации

**Назначение**  
Связь object type ↔ пункт меню / раздел.

**Что увидит пользователь**  
Раздел «Задачи» ведёт в реестр объекта.

**При изменении**  
Объект переедет в другое место меню.

**Связанные категории:** Навигация, Публикация типов объектов

---

#### Опубликованные быстрые формы

**Назначение**  
Quick create views, опубликованные для объектов.

**Что увидит пользователь**  
Кнопка «+» / быстрое создание с минимумом полей.

**При изменении**  
Другая форма быстрого создания; entry point исчезнет.

**Связанные категории:** Ядро (Действия), Элементы интерфейса (быстрое создание)

---

### Определение объекта ≠ опубликованный объект

| | Определение объекта | Опубликованный объект |
|---|---------------------|------------------------|
| **Суть** | Метаданные: поля, связи, правила | Snapshot «тип X в runtime tenant» |
| **Категория** | Ядро + Данные (Structure Metadata) | **Конфигурация** |
| **Где создаётся** | Designer | Publish → apply |
| **Аналогия** | Чертёж | Смонтированный продукт в здании |

## 9. Размещение модулей

---

#### Публикация модулей

**Назначение**  
Модуль **установлен** для tenant + entry points (menu, routes).

**Что увидит пользователь**  
Модуль доступен в Office (календарь, чат…).

**При изменении**  
Модуль включён или отключён для компании.

**Связанные категории:** Модули, Навигация (точки входа)

---

#### Настройки модулей компании

**Назначение**  
Tenant module settings после publish (validated by manifest).

**Что увидит пользователь**  
Поведение модуля для данной компании.

**При изменении**  
Другие параметры модуля (без смены capability).

**Связанные категории:** Данные (настройки компании), Модули

---

### Модуль ≠ опубликованный модуль

| | Модуль | Опубликованный модуль |
|---|--------|------------------------|
| **Суть** | Продуктовая capability платформы | Install + placement + settings для tenant |
| **Категория** | **Модули** | **Конфигурация** |
| **Пример** | «Календарь» как продукт | Календарь включён у ООО Розетка, пункт в меню, settings |

## 10. Размещение элементов интерфейса

Размещение [элементов интерфейса](./YASNOPRO_INTERFACE_ELEMENTS.md) в опубликованной оболочке — **конфигурация**; taxonomy элемента — отдельная категория.

#### Компоновка оболочки приложения

**Назначение**  
App Shell layout: sidebar, header, body, workspace chrome.

**Что увидит пользователь**  
Общую «рамку» Office/Studio.

**При изменении**  
Другая компоновка shell (например, без sidebar).

**Связанные категории:** Элементы интерфейса (глобальная оболочка), Компоненты

---

#### Размещение зон верхней панели

**Назначение**  
Порядок и наличие зон header: поиск, уведомления, профиль, переключатель контекста.

**Что увидит пользователь**  
Верхнюю панель с нужными элементами.

**При изменении**  
Поиск или колокол переедут; зона исчезнет.

**Связанные категории:** Элементы интерфейса (верхняя панель, пользовательский блок)

---

#### Видимость элементов интерфейса

**Назначение**  
Enable/disable UX-зон по типу экрана или tenant policy.

**Что увидит пользователь**  
Скрытые хлебные крошки, отключённый drawer и т.п.

**При изменении**  
Элемент перестанет отображаться.

**Связанные категории:** Элементы интерфейса, Стандарты

---

#### Брендинг портала

**Назначение**  
Логотип, название портала, цвета tenant в оболочке.

**Что увидит пользователь**  
Бренд компании в header и login.

**При изменении**  
Другой логотип и цветовая схема.

**Связанные категории:** Данные (настройки компании), Стандарты (accent zones — platform level)

---

### Элемент интерфейса ≠ размещение элемента

| Элемент (taxonomy) | Размещение (конфигурация) |
|--------------------|---------------------------|
| **Глобальный поиск** — что это за зона | Включён в header, порядок слева/справа |
| **Центр уведомлений** — зона агрегации | Колокол visible, overlay policy |
| **Меню пользователя** — зона профиля | Пункты меню, позиция у аватара |
| **Хлебные крошки** — ориентация | Показ на object pages / скрытие |
| **Быстрое создание** — паттерн UX | Для каких объектов, где кнопка |

**Логотип:** не отдельный элемент taxonomy v1.0 — **брендинг портала** (конфигурация).

## 11. Размещение действий

---

#### Действия панели списка и страницы

**Назначение**  
Какие [действия ядра](./YASNOPRO_CORE_ARCHITECTURE.md) показаны на toolbar списка/страницы.

**Что увидит пользователь**  
«Создать», «Экспорт», «Импорт» на панели действий.

**При изменении**  
Кнопки появятся или исчезнут с toolbar.

**Связанные категории:** Ядро (Действия), Элементы интерфейса (панель действий)

---

#### Действия карточки объекта

**Назначение**  
Набор команд на карточке записи.

**Что увидит пользователь**  
«Сохранить», «Согласовать», «Архивировать» в карточке.

**При изменении**  
Другой набор кнопок на карточке.

**Связанные категории:** Ядро (Действия), Элементы интерфейса (карточка объекта)

---

#### Контекстные действия

**Назначение**  
Команды в контекстном меню строки/объекта.

**Что увидит пользователь**  
Пункты «⋯» / правый клик.

**При изменении**  
«Опубликовать» переедет из toolbar в контекстное menu.

**Связанные категории:** Ядро (Действия), Элементы интерфейса (контекстное меню)

---

#### Группы и порядок действий

**Назначение**  
Группировка, primary/secondary, sort actions.

**Что увидит пользователь**  
Группы кнопок и их порядок.

**При изменении**  
Иная группировка без смены определений действий.

**Связанные категории:** Ядро (Действия), Стандарты UX

---

### Действие ≠ размещение действия

| | Действие | Размещение действия |
|---|----------|---------------------|
| **Суть** | Определение команды (create, approve) | Где показать команду |
| **Категория** | **Ядро (Действия)** + Доступ | **Конфигурация** |
| **Пример** | Action «Согласовать» существует | Кнопка на карточке, не в toolbar |

## 12. Стартовые роли и доступ

---

#### Стартовые роли и доступ

**Назначение**  
Bootstrap roles и default assignments при создании компании из Эталона.

**Что увидит пользователь**  
Права «из коробки»: кто что видит в новой компании.

**При изменении**  
Другой набор ролей; иной default для нового пользователя.

**Связанные категории:** Ядро (Доступ), Данные (Identity), Provisioning

---

### Роль ≠ стартовый набор ролей компании

| | Роль (модель) | Стартовый набор |
|---|---------------|-----------------|
| **Суть** | Permission model, role definition | Опубликованный набор для tenant |
| **Категория** | **Ядро (Доступ)** | **Конфигурация** |

## 13. Стартовая конфигурация компании

---

#### Стартовый профиль компании

**Назначение**  
Initial assembly tenant при provisioning из **Эталона**: nav + pages + objects + modules + roles + branding snapshot.

**Что увидит пользователь**  
Новая компания «как задумано платформой» (например, demo ООО Розетка из template).

**При изменении**  
Другой baseline для всех новых компаний.

**Связанные категории:** Provisioning (служба), Публикация, Runtime (materialization)

**Что получает новая компания из Эталона:**

- опубликованное меню и страницы;
- включённые объекты и представления;
- установленные модули и их settings;
- стартовые роли;
- брендинг и shell placement;
- ссылка на **опубликованный каталог** как единый snapshot.

---

## 14. Опубликованный каталог платформы

---

#### Опубликованный каталог платформы

**Назначение**  
Materialized **publish snapshot** — единая опубликованная структура tenant для runtime.

**Что увидит пользователь**  
Совокупность всего видимого: «как устроен портал компании».

**При изменении**  
После publish/apply — обновлённая структура Office.

**Связанные категории:** Публикация, Данные (materialized catalog), Runtime (host)

**Что входит в опубликованную структуру:**

- navigation tree и menu items;
- pages, sections, blocks;
- workspace definitions и system tabs;
- exposed object types, views, nav bindings;
- installed modules и module settings;
- UI shell placement и action placement;
- startup roles snapshot;
- **не входит:** business records, user personal tabs, runtime session state.

---

## 15. Границы категории

### Конфигурация ↔ Ядро

| Ядро | Конфигурация |
|------|--------------|
| Navigation engine, Actions, View Engine, Objects model | Published nav tree, action placement, views in runtime |

### Конфигурация ↔ Модули

| Модули | Конфигурация |
|--------|--------------|
| Capability «BPMN», «Чат» | Module installed, menu entry, tenant settings |

### Конфигурация ↔ Данные

| Данные | Конфигурация |
|--------|--------------|
| Structure Metadata, Tenant settings **storage** | **Role** of published assembly; snapshot semantics |

### Конфигурация ↔ Элементы интерфейса

| Элементы интерфейса | Конфигурация |
|---------------------|--------------|
| Taxonomy UX-зон (боковое меню, поиск) | Placement, visibility, shell layout |

### Конфигурация ↔ Публикация

| Публикация | Конфигурация |
|------------|--------------|
| Release Package, verify, apply | **Что** доставляется как config snapshot |

### Конфигурация ↔ Runtime

| Runtime | Конфигурация |
|---------|--------------|
| DEV / Эталон / Компания slot | Content UX **inside** company runtime |

## 16. Конфигурация и релизы

```text
Состав релиза =
  Архитектурные изменения (ядро, модули, службы, компоненты…)
+
  Конфигурационные изменения (nav, pages, placement, startup…)
```

**Release Scope** должен явно указывать конфигурационные артефакты, materialized при apply.

### Пример: модуль BPMN

| Слой | Что меняется | Категория |
|------|--------------|-----------|
| Новая capability workflow | Модуль BPMN в реестре модулей | **Модули** |
| Publish BPMN для tenant | Install + menu «Процессы» | **Конфигурация** |
| Toolbar «Запустить процесс» | Action placement на card | **Конфигурация** |
| Engine исполнения процесса | Workflow runtime | **Ядро / Модули** |
| Доставка в CLIENT | Release apply | **Публикация** |

Пользователь после релиза **видит** BPMN через **конфигурацию** (меню, страницы, действия), не через изменение taxonomy элементов интерфейса.

## 18. Использование документа

Документ применяется для:

- **архитектуры** — классификация publish artifacts;
- **публикаций** — что входит в catalog snapshot;
- **релизов** — Release Scope для конфигурационных изменений;
- **создания компаний** — стартовый профиль из Эталона;
- **аудитов** — drift между Designer intent и runtime;
- **онбординга** — как устроен «видимый» портал tenant.

**Следующий шаг governance:** добавить категорию «Конфигурация» в [Архитектурную классификацию](./YASNOPRO_ARCHITECTURE_CLASSIFICATION.md) и реестр DEV Studio (отдельный WI).
